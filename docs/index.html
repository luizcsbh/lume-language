WASM → Worker → DOM tipado

01 / EXPERIMENTE

Rode localmente

Extraia o ZIP e, na pasta do projeto, inicie um servidor HTTP local com Python 3. Não é preciso instalar pacotes npm.

unzip lume-language-main.zip
cd lume-language-main
python3 -m http.server 8000

Depois abra http://localhost:8000. Use um navegador moderno com suporte a WebAssembly e Web Workers.

02 / EXPLORE

Uma linguagem pequena

O protótipo inclui funções, variáveis, condições, laços, tipos i32, f64 e bool, exemplos de Canvas e uma API DOM de alvos registrados.

O heap experimental armazena células i32 sob handles opacos. Não oferece strings, ponteiros brutos ou acesso direto à memória WASM.

03 / LEIA ANTES

Limites e segurança

WebAssembly e Web Workers não são, por si só, uma sandbox para código hostil. Execute somente programas que você entende e controla; código pode consumir CPU até a execução ser interrompida.

A revisão e os limites implementados reduzem riscos conhecidos, mas não garantem ausência de vulnerabilidades. WASM também não é automaticamente mais rápido que JavaScript.

04 / PRIMEIROS PASSOS

Comece a usar o Lume

Abra o playground deste repositório ou rode o projeto localmente. No editor, escolha um exemplo ou escreva seu programa; clique em Compilar para validar e em Executar para rodar no navegador.

Para rodar localmente, baixe o código-fonte, inicie o servidor na pasta do projeto e abra o endereço local:

python3 -m http.server 8000

Depois, abra http://localhost:8000 no navegador.

05 / HELLO WORLD, LUME

Seu primeiro programa

fn main() -> i32 {
  print("Olá, Lume!");
  return 0;
}

Cole o código no editor e clique em Executar. O console mostrará Olá, Lume!.

06 / NO SEU PROJETO

Como adicionar o Lume

O Lume ainda não é um pacote npm nem um runtime pronto para instalar em outro app. Use o repositório como ponto de partida: adapte o compilador em src/compiler.js, o Worker em src/worker.js e forneça no host JavaScript as funções importadas pelo programa.

Para experimentar sem integração, use o playground deste projeto. Não basta adicionar uma tag <script>: a execução depende do compilador, do Web Worker e das importações de host.
